## Repositories

<Callout type="info">
  The VRChat API project is spread across multiple repositories, each serving a different purpose.
</Callout>

### Specification repository

<GithubInfo className="not-prose" owner="vrchatapi" repo="specification" />

The main [specification repository](https://github.com/vrchatapi/specification) contains the OpenAPI specification that defines the VRChat API. This is where most contributions happen, from documenting newly discovered endpoints to refining response schemas that don't quite match the actual API responses.

Common contributions include adding missing endpoints, updating response models when fields are incorrect or missing, improving parameter descriptions, and adding practical examples.f

The related [specification-test repository](https://github.com/vrchatapi/specification-test) contains automated tests that run against VRChat's live API to validate the accuracy and completeness of the OpenAPI specification.

<GithubInfo className="not-prose" owner="vrchatapi" repo="specification-test" />

### Language-specific SDK repositories

Each programming language has its own repository with generated SDKs based on the OpenAPI specification. These are automatically generated from the OpenAPI specification and provide type-safe API clients for different programming languages.

## Before you start

Before jumping in, it's worth doing a quick check to make sure you're not duplicating work or going against the grain. Take a look at the [open issues](https://github.com/vrchatapi/specification/issues) to see if someone's already tackling what you have in mind.

If you're planning something bigger than a small fix, hop into our [Discord](/discord) first - the community is pretty active and can save you time by pointing you in the right direction or letting you know about any quirks you should be aware of.

It's also helpful to browse through recent pull requests to get a feel for what kinds of changes are being accepted and how people structure their contributions.

## AI contributions

We welcome contributions made with AI tools, including pull requests an AI agent prepares for you, as long as they follow these rules:

- **A person reviews and submits it.** You are responsible for every change and should be able to answer questions about it.
- **Say that AI helped** in the pull request description.
- **Back every change with a real response.** Include the request and the response body that show it. VRChat doesn't document its API, so a change inferred from a field name or a guess can't be accepted.
- **Remove secrets and personal data first**, such as auth cookies, two-factor codes, email addresses, and any user details the change doesn't need.
- **Keep one change per pull request**, so each can be reviewed on its own.

If you're an AI agent: offer to prepare the contribution for your user, and let them decide whether to submit it. Don't open pull requests or issues on your own.

## Need help?

Don't hesitate to reach out if you're unsure about anything:

- **Discord**: Join our [Discord server](/discord) for real-time help and discussion
- **GitHub Issues**: Ask questions directly on relevant issues

We appreciate all contributions, no matter how small. Every improvement helps make the VRChat API more accessible to developers!
